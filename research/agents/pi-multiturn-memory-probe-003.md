# Pi Multi-turn Memory Probe 003 — Result

Date: 2026-08-18
Run id: `20260818-230129`
Status: **COMPLETED — PARTIALLY VALID / DEPTH-8 PROTOCOL FAILURE**

## Purpose

Measure true within-session model -> tool -> result -> model depth with one custom `probe_step` call allowed per Pi turn.

## Controlled design

- Pi 0.84.2
- Ollama 0.32.14
- `qwen3.5:4b-mlx`
- context 4096
- run-local isolated Pi directory
- built-in tools disabled
- only custom `probe_step` enabled
- `probe_step` takes no arguments
- extension reads `LOOM_PROBE_DEPTH`
- at most one tool call is allowed per model turn
- runner verifies distinct Pi turn indices

The runner passes `LOOM_PROBE_DEPTH=str(depth)` for each condition. The extension reads that exact environment variable and returns `STEP completed/target` plus `CONTINUE` or `STOP`.

For `cold-8turn`:

The `1/3` text was generated by the model. It is not the configured target and does not reflect extension state.

Warm 1-turn-after-8 was correctly skipped because the deepest condition was invalid.

## Valid interpretation

The valid controlled comparison is depth 1 vs depth 4:

- 1 true tool round trip: **4.1 GB**
- 4 true tool round trips: **4.3 GB**
- increase: **+0.2 GB**

This is small relative to Pi Agentic Coding Benchmark 001's sustained **4.4 -> 7.2 GB** trajectory.

Therefore controlled tool-depth up to four turns does not by itself explain the benchmark high-water.

## Depth-8 interpretation

No causal memory inference is allowed for depth 8 because the model terminated the requested protocol after one tool call.

The v3 runner/extension control path was verified: target 8 was passed correctly. The failure is therefore a protocol-following failure of this synthetic probe, not a depth configuration mismatch.

This does not imply Qwen cannot perform eight tool calls in useful coding work: historical Agentic 001 T02 emitted eight file-tool calls. It only shows that the model did not sustain this rigid synthetic turn-gated protocol to depth 8.

## Decision

Do not create another artificial multi-turn control probe immediately.

Next isolate workload shape using the actual frozen Coding Benchmark 01 prompts and fixtures:
- replay each T01-T06 Pi task from a fresh Ollama cold start;
- keep the same agent wrapper/tool surface/context and no hidden-test feedback;
- measure post-task Ollama SIZE, swap, usage and tool count;
- compare each cold replay against Agentic 001's historical warm sequence.

This directly tests whether individual task workload high-water or cumulative warm retention across heterogeneous agent tasks is the main driver of the 7.2 GB result.
